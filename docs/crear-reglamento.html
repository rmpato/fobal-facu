📝 Crear un reglamento nuevo

Para correr partidos con v1.2, v2 o v3 no hace falta “promptear para que pushee solo”. Editás archivos en el repo, corrés el simulador en tu máquina y, si querés publicar, hacés commit + push.

Respuesta corta

El simulador ya está armado para reglamentos versionados. En la mayoría de los casos alcanza con tres archivos (Markdown + JSON + índice) y un comando en la terminal. Cursor u otra IA son opcionales: te ayudan a redactar, pero el flujo normal es editar el repo como cualquier código.

Pasos para una versión nueva

PasoArchivoQué hacés
1 docs/reglamento-vX.md Reglas para jugar en mesa (texto humano)
2 reglamentos/vX.json Especificación que lee el motor del simulador
3 reglamentos/indice.json Registrás el id en el catálogo
4 Terminal python3 -m simulador run --reglamento vX --partidos 200

Guía técnica completa en el repo: reglamentos-guia.md · plantilla: _plantilla.json

Cambio chico (como v1.1)

Si solo cambiás una regla sobre la versión anterior, un JSON corto que extiende la base alcanza — sin tocar Python.

Ejemplo real: reglamentos/v1.1.json extiende v1 y solo overridea qué pasa si nadie reacciona al pasa de turno:

{
  "id": "v1.2",
  "nombre": "Iteración 1.2",
  "version": "1.2",
  "documento": "docs/reglamento-v1.2.md",
  "descripcion": "Qué cambia respecto a v1.",
  "extends": "v1",
  "reglas": {
    "pasa_turno_sin_respuesta": "pasa_companero"
  }
}

Guardalo como reglamentos/v1.2.json y agregalo al índice.

Cambio grande o reglamento desde cero

  1. Copiá reglamentos/_plantilla.json → reglamentos/v3.json
  2. Completá mazo, partido, reposición, acciones, reacciones y reglas.*
  3. Elegí motor_perfil: v0 o v1 según la lógica de turno que necesitás hoy
  4. Creá docs/reglamento-v3.md con el texto para mesa

Mientras la mecánica quepa en los campos del JSON, no hace falta modificar el simulador.

Cuándo sí hay que tocar código Python

Solo si inventás una regla que todavía no está modelada en el JSON o el motor, por ejemplo:

  • Un tipo de turno distinto que no sea perfil v0 o v1
  • Una carta nueva con lógica especial no expresable en reacciones / reglas.*
  • Una resolución de dados o flujo de partido que el motor no conoce

Ahí alguien edita simulador/ (a mano o con Cursor). Sigue siendo código normal del repo — commit y push como siempre.

¿Cursor o editar directo?

FormaCuándo usarla
Editar directo
VS Code, GitHub web, etc.		 Cambios de reglas que ya entran en el JSON — camino principal
Pedirle a Cursor / IA Redactar el MD, armar el JSON, actualizar la web (docs/*.html) o implementar lógica nueva en Python
Push a GitHub Siempre manual: git commit + git push. La IA puede hacerlo si se lo pedís explícitamente

Push y sitio web

  • Simular en tu PC — con tener el JSON en el repo clonado alcanza; no hace falta push.
  • Compartir con el grupo — push a main sube el código; quien clone puede correr el mismo reglamento.
  • Actualizar esta web — GitHub Pages sirve la carpeta docs/ desde main. Cada push actualiza el sitio en ~1–2 min (solo lo que esté en los HTML/MD de docs/).

Opcional: después de simular, actualizá números en resultados.html o reglas.html antes del push.

Variantes vs reglamentos

Reglamento (reglamentos/*.json): versión formal del juego (v1, v1.1, v2…). Variante (configs/variantes.json): ajuste de simulación (IA, límites) sin crear reglamento nuevo.

Si el cambio ya es regla de juego (como “pasa al compañero”), preferí un reglamento nuevo en lugar de un flag suelto.
